      Why route first

      A small local model is slow and it wanders. So before any model sees a turn, plain code asks a fixed list of questions in a fixed order, and the first yes decides. A request to save the conversation never reaches a model at all: a playbook reads the transcript and writes the file.

      Only a message that falls through every check pays for a model call to work out what it is. The open-ended loop, where the model picks tools for itself, is the last resort and not the default.

      What is real here

      The order of the checks, the reason printed under Decision, the gates in front of each tool and the words of each block message are the ones in WITS. The injection patterns and the personal-data patterns are copied whole. The phrase lists are shortened, so the real router recognizes more than this page does.

      Where a tool is named under the orchestrator, it is the tool the route points at. A real model can still choose badly, which is what the gates are for. A named file is checked against the folders the owner has allowed; this page has no disk, so a path that climbs out of the project stands in for one that fails that check. The whole port is one script.

      What it leaves out

      Follow-ups to an earlier turn, the content rules for younger guests, and the limit on repeating a failed tool call. It also leaves out the one door to the outside: when the local model is stuck it can queue a question for a larger hosted model, and nothing is sent until the owner approves that single request.
